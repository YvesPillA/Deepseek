# 架构、验证边界与回滚

“新工头模式”让执行负责人拆分阶段并派工，让多个监督者独立审查，外层主代理负责用户确认与最终交付。本机已验证 DeepSeek Harness Desktop **0.2.0-rc.2**（实际安装包 buildCommit `04f392c9ddd144fa426da2045178797da6db6c11`）；包声明另支持已验证的 `0.1.7-rc.2`。其他宿主版本需重新验证，不能仅按相近版本号安装。

本机发布使用 DSH 自带的 Windows 本机验证服务，**只启动 DSH 即可使用新工头，无需启动 Docker**。正式宿主仍需完整接线和匹配实际 Electron 安装包、插件文件、验证后端及四类验收证据的发布批准；配置布尔值不能替代宿主批准。本仓库提供源码、测试和发布工具，不包含任何用户会话、密钥、工作项目或本机发布凭据，克隆到另一台电脑不会自动获得原机器的发布批准。

## 使用流程

1. 在 DSH 模式菜单选择“新工头模式”，通过普通聊天说明项目需求。外层主代理提出执行负责人、监督名单和审查规则，由用户通过原生确认开局；执行者不能代签。
2. 执行负责人规划里程碑并派工，执行者提交实现及快照验证结果，监督者按各自职责独立验收。规划轮审查方案，成品验收轮才读取交付证据。全员通过才放行；默认同一里程碑累计第 3 轮否决后暂停并交用户裁决，独立分支可继续。
3. 阶段全部完成后进行最终监督验收，外层通过原生交付确认收尾。用户可拒绝或同意；模型工具调用不能自行代替这次确认。
4. 已取消或已交付的项目可在面板点“归档项目”，确认后从当前列表移除。在“已归档”中可恢复显示或再次确认“删除记录”。删除后不能在面板恢复，旧项目 ID、原始审计和工作区文件保留。恢复显示不会重新执行任务。聊天入口的管理请求仍经原生确认后生效。

侧栏进度面板显示阶段、任务、监督结果及待处理事项。应用打开时会检查重大问题，通过浮层提示待裁决、技术故障和等待交付；普通进度不提示。“暂时收起”只影响本次显示。断线时标注旧数据并退避重试。

状态、发送队列、任务重试、否决次数和审计记录持久保存。巡查按完成任务数触发，只记录意见。DSH 使用共享 standing mount，工具执行时校验真实 agent 与作用域成员关系，各会话的确认与撤销分别管理；宿主卸载或会话注销会取消未完成确认，迟到答案不能提交。

开局的目录准备与确认分离：准备阶段只检查现有目录或现有父目录下的缺失子目录，不写文件。缺失目录在原生确认后由宿主创建，并重查身份、父目录、保护范围和项目占用；不会递归建父目录、合并突然出现的目录或在失败时递归删除文件。已删除且结束的记录释放目录占用，旧 ID 仍永久保留；同名新草案分配新 ID 并展示在确认卡上，确认时不再悄悄换号。运行中、仅取消或归档的项目继续保留目录隔离。

内部代理由宿主独立拥有，新会话通过官方 `origin:subagent` 元数据从普通会话列表分离，不建立虚构的父代理关系。标题使用官方会话标题服务，包含项目、角色和任务或审查信息。项目结束后，仅归档本插件能唯一确认归属、已停止的内部会话；用户外层对话不受影响。旧会话保留原始内容与元数据，通过官方工作区归档服务收拢。

简单单文件目标建议采用最少且合理的里程碑，避免按监督职责机械拆成多个串行阶段。负责人默认读取精简进度，已完成任务和已通过审查的长说明按需用 `foreman_detail` 获取；失败与返工要求、锁定监督标准始终保留。`foreman_read` 的可选游标只减少同回合内的重复材料；新回合、压缩或上下文替换会使旧基线失效。等待执行或审查时结束当前回合，由宿主唤醒，不反复轮询。研究依据、离线测量与限制见 [上下文效率](efficiency.md)。模型推理与服务端响应仍会影响实际速度，不保证固定完成时间。

## 验证与边界

实际 0.2.0-rc.2 下的小型 Node 项目已完成两个阶段、独立监督、最终全员验收和用户原生交付确认。实际 Electron 的模式菜单及侧栏面板、实际新版后端的原生确认与空会话接管、真实宿主工具和作用域权限均有验收记录。收费项目使用隔离的官方 API-key 路由；它不能替代用户 Desktop 默认账号路由的登录与连通性检查。

本机后端使用实际 0.2.0-rc.2 的 sandbox/subprocess 服务。每次将项目快照按字节复制到独立临时目录，仅给该副本授予写权限；真实工作区、监督配置、会话和插件目录不授写。命令有执行时限、输出上限及 Windows Job 进程树清理；取消或清理失败不能变成成功证据。宿主环境变量采用基本系统变量白名单，验证产生的文件与依赖不会回写项目。执行者的 `foreman_verify` 生成持久结果，监督者的 `foreman_evidence` 只读取与本轮验收快照匹配、已完成清理的结果，并明确区分本机和容器证据。应在最终整理和临时文件清理之后验证；随后改动或删除捕获文件会改变快照，需重新验证。“当前快照无证据”不等于历史从未运行过验证。

`node` 使用 DSH 自带运行时；Node 测试使用 `node --test --test-isolation=none`。其他命令需要本机已有相应工具。官方 Windows 沙箱限制普通文件写入，**不隔离读取、网络或进程可见性，也不提供容器的 CPU/内存/PID 限额**；部分使用孙进程管道的 npm、构建或浏览器工具链可能不兼容，不能声称任意项目已验证。执行角色仍没有配置、监督规则或原生 shell 管理工具。只读快照和身份规则继续生效，不把部分本机隔离描述为完全隔离。

本机验证不会因存在 `package.json`/lockfile 要求 Docker 依赖镜像。它不复制宿主 `node_modules`；需要临时依赖时，应在同一次验证命令中完成安装和测试，使用本机已有工具，并如实报告工具缺失或沙箱不兼容。不会隐式启用原来的镜像构建服务。

旧 Docker 后端作为显式可选配置保留：固定 Linux Node 镜像、禁网验证、资源限制，以及 lockfile v3 公共 npm 镜像供应和原生候选批准流程均保持原行为。只有选择该后端才需要 Docker。新版本机发布批准与旧 Docker 批准互不通用，旧容器账本和验收证据仍可读取。

超时、取消和创建结果不明保留原审计，不作为“后台已停止”的证明。重启后未结束的本机验证记为 interrupted，保留旧临时目录，不伪称已清理或通过。Docker 依赖恢复只核对原候选镜像，不盲目重建。空会话接管需原生确认并停止、排空旧代理；有持久内容、已确认送达、身份仍活跃、配置变化或停止失败时拒绝接管。接管保留工作文件、监督规则、否决次数及队列历史，新执行者先核查现状。

宿主可配置 `scheduler.executionTimeoutMs`（1–86400000 毫秒，默认 null）。已确认送达的任务才开始计时，墙钟期限包含停机时间，重启或改配置不刷新它；到期先停止并排空执行代理，再记录失败，由负责人决定是否重试，不增加监督否决次数。

## 发布、备份与回滚

Desktop 有独立 profile 和插件包目录。发布工具只使用显式 home/profile/candidate，保留其他插件、用户默认模型、会话和存储；scheduler 取当前默认模型的 provider/model/reasoningEffort 白名单，不复制账号或 API credential。官方 provider 注册与目录存在不表示账号已登录或模型端点已连通。

先只读审查升级计划，在宿主停止、profile lock 与 writer guard 可取得后安装精确候选，再审查发布配置计划。`scripts/prepare-desktop-release.mjs` 要求四类真实证据（Desktop UI、恢复、项目最终交付、源码回归）和 patch/package/review 三个 hash，才允许受保护配置 apply。本机发布输入设置 `verificationBackend:"native"`，不要求 Docker 参数；宿主配置为 `verification:{backend:"native"}`。工具复制普通证据文件并始终生成 `approved:false` 草稿；明确的 host 审查批准及实际 Electron 门禁检查是独立步骤，工具不能自发批准。改包、验证后端、镜像或证据会撤销原验证，需重新审查。

发布配置 receipt 必须保留。**回滚顺序是先撤销发布批准/配置引用、回滚配置 receipt，再回滚 Desktop 升级 receipt。** 已配置 patch 使用官方后置 override；再次升级前也须先配置回滚。用户之后改过 package 或 patch 时，hash 守卫拒绝覆盖，应人工合并。具体接口见 `scripts/upgrade-local-rc2.mjs` 与 `scripts/prepare-desktop-release.mjs`。包含本机路径和用户项目内容的发布记录仅在本地保存。

日志使用带校验值的状态增量，兼容读取旧版完整状态日志；只有完整换行的记录才算提交，不自动压缩或删除历史。**新格式写入后，2026-09-15 安装的旧代码不能读取它。** 升级前须停机备份数据目录；回退旧代码不能直接配用新日志。恢复升级前备份会丢失升级后的变更，不能视为无损回退。

Windows 日志锁依赖 `koffi`，`writer.guard` 使用 Win32 `LockFileEx` 内核锁，进程崩溃后可接管本协议遗留 marker；不要删除运行中的锁。旧版活跃 PID、损坏 marker 或完整日志行损坏均拒绝接管，其他系统保守保留文件锁。

## 开发入口

- `src/host.mjs`：宿主装配、只读服务和面板 RPC；只有实际认证的 operator 可使用专门的归档、恢复和删除记录接口，不能通过它发起任意管理命令。`src/outer-entry.mjs`：外层模式及真实会话身份。
- `src/session-presentation.mjs`：内部会话命名和结束后的归档。`src/state-delta.mjs`：有界、临时的状态增量缓存。
- `src/managed-runtime.mjs`、`src/runtime-loop.mjs`：自动调度、停止排空和恢复。
- `presets/foreman-next/`、`client/index.js`：模式定义及侧栏面板。
- `test/`：离线规则、文件权限、日志、回滚及本机 DSH 合约。

```powershell
node --test test/*.test.mjs
```

`DSH_TEST_INSTALL` 可指定测试用 DSH 安装目录，发布工具另使用 `DSH_RUNTIME_ROOT` 选择已核对的实际 runtime。本机开发的 scope/koffi junction 不能作为可分发依赖；正式包需正常解析声明的 peer/optional dependency。构建候选使用 `scripts/stage-release.mjs`，该命令只冻结文件和哈希，不安装或修改用户配置。
