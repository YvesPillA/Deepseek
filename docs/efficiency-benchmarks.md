# 效率实验记录

实验日期：2026-10-08～09。**三组候选的费用均回退，均未默认上线。** 最终采用的重复历史材料清理只声称减少投影字节；其账单和全项目速度收益尚未实测。

## 方法

官方 DeepSeek Anthropic 路由、deepseek-flash、high、每次最多 8192 输出 token；两组参数相同。没有提供方随机种子，不能声称确定性采样。前两轮各三种场景、两次重复，顺序 AB/BA，共各 12 次；第三轮只剩有限请求预算，固定做长成功验证的一个 AB 配对，共 2 次。没有删除失败或工具错误，之后也没有为凑有利结果继续付费。

场景为脚本新建的合成项目：60 项 Node 加法测试的成功验收；exitCode=0 但中段出现 RESULT:FAIL 的业务失败验收；四文件收据逻辑修复（quantity 与 Math.round）。监督票须与预期一致并读取文件和精确快照证据；执行者须实际运行原有三项测试、保持测试原件，并通过宿主隐藏用例。规划、开局确认由确定性宿主 fixture 完成。它们是单角色工具循环实验，**不等于整项目、多监督者或 GUI 端到端性能**。

实验 1：联合批量／范围读取与成功 TAP 精简的参考候选。实验 2：加入首次材料交接并缩短说明，采用实际 complete system-section 行为。实验 3：撤下新工具，仅保留简化交接。完整返回视图可能促使模型补读，提示词变化也会影响输出和缓存；各实验分别与其匹配 baseline 比较，不将不同轮的随机差异归因于单项算法。

26/26 次均通过各自质量门槛。实验 1 费用增加 13.92%，实验 2 增加 50.85%；模型反复补读和额外说明抵消了工具返回量下降。实验 3 请求 4→3、输入 token 减少 6.83%、耗时减少 7.00%，但输出增加 58.74%，费用增加 32.83%；只有一个配对，不能宣称统计显著或普遍提速。因此没有按“少一次请求”将它作为省钱优化安装。

三轮累计 117 次实际请求、29,566 输出 token，价格上界估算 USD 0.075089。计量账本逐次继承，120 次／400,000 输出 token／USD 3 的累计上限没有重置；隔日续跑仅显式更新过时间窗口。没有调用额外摘要模型、改变用户的 high 或删减监督人数。

## 最终保留

已通过且关闭的审查 payload 从负责人经常读取的投影中移出，保留详情入口；需要历史全文时用 foreman_detail。未决、否决、无明确通过结果的材料继续内联。当前任务、里程碑标准、监督规则和负票保留。监督唤醒消息不再再次抄写系统角色说明已有的阶段段落。两项均由固定源事件生成视图，不重写持久记录或已有聊天。

这是保守的冗余清理；离线验证检查少发了哪些字节以及全文能否恢复，不能据此给出实际费用下降比例。研究依据及未采用技术见[研究说明](efficiency-research.md)。
