# 上下文效率

本轮优先减少重复工具材料，保留监督与完成标准。负责人 `foreman_read` 支持可选 `sinceCursor`：首次读取 `{}` 得到完整状态与 `_read.cursor`；保留基线后传该游标，宿主返回变化或无变化。丢失基线、压缩后、恢复后或不确定时重新读取 `{}`。

`_read.full=true` 表示替换整个基线。`full=false` 带 `baseCursor`、新 `cursor` 和 `changes`；路径为字面键数组，`set` 替换整个值，数组也整体替换，`remove` 删除对象键。未知、其他装配实例、缓存淘汰的游标均返回全量；变化比全量更大时也返回全量。每个角色装配最多缓存 4 个状态、1 MiB JSON，缓存只在内存中存在。宿主看到本会话压缩摘要、新回合开始或 surface 替换代际变化时，会清空缓存；即使模型误传旧游标也返回全量，避免模型基线被压缩后继续只收到增量。

游标只是性能提示。每次调用仍检查宿主绑定的真实 agent 对象、项目、配置版本及取消状态。监督职责、当前任务、负票原文和返工指向继续保留；完整历史仍由负责人按需使用 `foreman_detail` 读取。监督者与执行者没有获得增量读取或额外权限，全监督一致通过、三次否决暂停和阶段边界保持原有规则。

一个既有诊断样本的 19 次负责人读取，在离线回放中从原始 292,913 字符，经上轮历史投影压缩至 155,954，再由本轮增量协议降至 90,987：比上轮少 41.7%，比原始少 68.9%。回放包含实际记录的新回合与压缩事件，并在每次边界后重取全量；其中 7 次全量、9 次变化、3 次无变化，逐次重建状态均与完整投影一致。此实验假设调用者在同一回合保留基线并在后续读取传游标。字符数不是 token 或计费数，不包含新增参数和提示词开销，也没有删除已有会话历史；尚无新模型耗时或费用实测。

DSH 0.2 提供 `agentOptions.reasoningEffort` 和 `maxTokens`。当前 DeepSeek 适配器支持 `off/low/high/max`，输出上限会结束达到限制的回合，不能把截断当作完成。DSH 自带基础压缩引擎支持压力触发与持久摘要，但摘要会额外调用模型。本轮没有修改用户模型、`high`、输出预算、profile，也没有启用额外摘要。未来预算应由用户明确配置，并对截断、中断及任务继续行为单独验收。

研究用于选择可验证的小改动，不将其他框架或基准收益直接等同于本项目收益：

- [The Complexity Trap（2025，原始论文）](https://arxiv.org/abs/2508.21433)：旧工具观察的简单遮蔽在论文的编码代理实验中可与模型摘要竞争，支持先考虑确定性减少重复观察。
- [DTOC（2026，原始论文）](https://arxiv.org/abs/2609.26121)：外部保存完整输出、按需恢复是重要设计方向；模型间效果不同。这里采用可恢复的全文读取，没有移植其推理循环。
- [AgentFold（2025，原始论文）](https://arxiv.org/abs/2510.24699)：多尺度历史折叠需要相应训练，不能作为现用模型的即插即用能力。
- [AdaCoM（2026，原始论文）](https://arxiv.org/abs/2605.30785)：学习型上下文策略存在保真与可靠性取舍，本轮保留确定性事实，不引入新的模型管理器。
- [Anthropic 上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：支持按需取材料、避免不断堆积重复上下文；其产品接口不直接适用于 DeepSeek。
- [OpenAI Compaction 官方文档](https://developers.openai.com/api/docs/guides/compaction)：有服务端压缩窗口协议，但 opaque 压缩项及链式上下文规则属于其 API。本项目没有更换 API 或套用其参数。
