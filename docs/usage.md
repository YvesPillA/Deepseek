# 使用说明

开局目录可以选已有目录，也可以填已有父目录下的新子目录。新目录会在确认卡中注明，只有你确认开局后才创建；返回调整不会创建。父目录本身需要存在。

已删除且结束的项目不再占用原目录。若重做时用了旧项目 ID，确认卡会显示新的编号（例如 `example-2`），旧历史不会被覆盖。仅取消或归档的记录仍保留目录占用，需先删除记录再用该目录开新项目。运行项目的目录仍不能重叠。

## 开始项目

在 DSH 新会话中选择“新工头模式”，说明目标和工作目录。外层主代理会建议监督名单，每位负责一个方面；调整职责和验收标准后，通过原生确认开局。

简单单文件任务可以只用一个里程碑。监督人数、职责和验收标准应与实际目标相称，额外增强功能需要你确认后再纳入。

## 运行期间

执行负责人提出里程碑计划，全体监督者通过后派工。执行者负责修改文件和验证，监督者只提出问题与验收要求。阶段和最终验收都需要全员通过。

日常进度在“新工头模式”面板查看；权限申请、重大故障和需要你裁决的问题会单独提示。默认每完成3个任务巡检一次；单个里程碑累计第三轮否决后暂停，其他独立里程碑仍可继续。

## 结束、归档与删除

| 操作 | 结果 | 工作区文件 |
| --- | --- | --- |
| 终止项目 | 项目停止推进，保留当前进度 | 保留 |
| 归档项目 | 从当前项目列表移到“已归档” | 保留 |
| 恢复到项目列表 | 恢复显示，已结束任务不会重新运行 | 保留 |
| 删除记录 | 从当前和归档列表移除，此处不能恢复 | 保留 |

删除只对已经归档的已取消或已交付项目开放，并需要再次确认。它删除的是面板可管理的条目，不是整个目录；原始审计和旧项目ID仍保留，用于避免把旧消息误关联到新项目。它不是对历史文件的物理擦除。

不要删除共享工作区来清空面板。重新做同一目标时，创建一个新项目；同名编号已属于删除历史时，宿主会在确认卡中分配新编号。

## 内部会话

执行负责人、执行者和各轮监督者都有持久会话，用于断点恢复和核对审查依据。这些属于新工头的内部代理，不是你新建的普通聊天。

内部会话使用角色名称，并按 DSH 的内部会话分类处理，不应挤占普通侧栏。已结束项目的闲置内部会话使用官方归档功能收拢；它们的原始内容仍保留。你的外层工头聊天以及其他项目的普通聊天不会一起归档。

## 验证与速度

无需启动 Docker。本机命令在项目的临时副本中验证，生成的临时文件和依赖不会回写工作区。

先完成最终修改和临时文件清理，再运行验证。验证后修改或删除文件会改变快照，需要重新验证；“当前快照没有匹配证据”不代表历史上从未运行过验证。

模型推理和服务端响应仍可能花费较长时间。已有优化主要减少重复材料、重复状态读取及无效等待，不能保证每个任务在固定时间内完成。研究与测量范围见[效率说明](efficiency.md)。
